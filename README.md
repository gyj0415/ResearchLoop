# ResearchLoop

BoHack 2026 AI Research 本地 MVP v0.2。研究对象是**检索策略及其适用条件**：Agent 从失败类型提出假设，选择或生成受约束策略，开发筛选后完整评估，在一次独立验收后保存有条件的经验。

**所有推理使用本地 Ollama。云端调用关闭。没有编造的性能数字。** 随机搜索可在没有模型时使用，但会明确标注为确定性对照，不能发布 Agent 经验。

项目决策、参考资料、更新日志和第二版实测报告保存在本地 `docs/`，该目录按项目约定不随 Git 上传。首版历史实测保留在 [VERIFICATION.md](VERIFICATION.md)，不改写旧结果。

源码仓库不包含数据、模型、运行历史或打包产物。首次使用可在界面点击“准备公开数据”，或运行 `py -3.12 research.py prepare`；数据与任务清单会在本机生成。

## 启动

在当前文件夹双击 `start.bat`，或在 PowerShell 运行：

```powershell
cd D:\26bohack
.\start.ps1
```

浏览器打开 <http://127.0.0.1:8767>。需要 Python 3.12 或更新版本，运行时只使用标准库，不需要 pip / npm 安装。第二版使用独立端口，避免旧服务仍持有首版代码。

本机已有 Ollama 模型 `deepseek-r1:8b` 和 `deepseek-r1:14b`，模型目录为 `D:\models`。优先选 8b。启动脚本会尝试在后台开启已有 Ollama 服务，在页面右上角可检测服务和选择模型。也可手动运行 `ollama serve`。应用不会自动下载模型或切换云端。

## 完整体验

1. 在“研究工作台”开始任务 **C / Ollama Agent / 无历史经验**。旧 A/B 已查看，仅作开发诊断。
2. 查看假设、实验曲线、逐题检索证据和原始模型 usage。模型也可以自主停止，零候选实验不会被包装成成功研究。
3. 候选若在独立验收集的完整命中与覆盖率均不退化，且确实运行了候选实验，可以点击“发布经验”。小样本验收门槛不等于统计显著性。
4. 在任务 **D** 上，使用相同模型、种子、token、时间与实验上限，分别运行无经验 Agent、带经验 Agent、配置沿用、随机搜索。经验先按查询特征匹配，可能被拒绝；拒绝会记录理由，不会把它算作已使用经验。
5. 在“实验记录”比较 D 上的质量、实验次数和全部成本。不能直接相减 C/D 的分数，也不能把共享去重、筛选或沿用配置的收益当作研究能力提升。D 一旦用于分析，就成为已见开发任务；E/F 保留给后续新验证。
6. 在“研究经验”切换版本或回退到 v0。历史记录不会删除。
7. 所有方案冻结之后，再在“数据与评估”执行最终统一验收。仅冻结当前后端代码版本的完整运行，避免混用开发期间的旧算法版本。最终测试仅开放一次；之后的新版本不能再声称对它未见。

最终测试默认保持封存。开发检查不应触发这项操作。

## 实验边界

- 固定证据单元为 `(doc_id, sentence_index)`，返回最多 5 个唯一句子。
- 固定旧版 BM25 基线；允许缩写扩展、保守伪相关反馈、保留否定/数值的候选分词策略，以及最多三个可观测特征的 all/any 门控。扩展保留原查询，通过固定 RRF 融合。新分词仅在条件触发时启用，旧默认算法不变。
- 工具将开发失败分类为初始前50的召回缺失、部分召回或排序不足；不把开发金标用于新问题上的策略门控。
- 排除语义等价配置和在全部探索查询上不触发的干预；所有对照组共享该规则。固定8题先筛选，再进入完整探索，并用哈希校验复用同轮已算题目。连续两项未改善完整探索结果时停止，该规则同样共享。
- Agent 根据测量选择实验顺序、假设、适用条件和停止时机。配置只能从合法单因素候选中选择，不能修改数据或评估代码。
- Agent 下一次规划会看到探索集的改善和退化案例，独立验收反馈不会进入本轮后续优化。
- 无逐题 LLM 重排、无模型训练、无联网文献搜索。本 MVP 证明范围为摘要证据检索研究，不自动生成新的生物学发现。

## 数据与指标

SciFact 原始数据约 3 MB，已提供下载器和文件哈希检查。`data/scifact/` 保存源归档、原始标注、许可和冻结划分。

- 旧 A/B：各40道探索 + 20道验收，已用于开发分析。
- 新 C/D：各24道探索 + 12道验收，固定8道探索题作为开发筛选子集。
- 预留 E/F：各24道探索 + 12道验收，暂不运行。
- 最终测试：从官方开发集保留 80 道题。
- 按共享标注证据文档连通分组隔离。原划分种子2026，新任务种子20261114；新任务排除与旧任务及最终测试关联的整个连通分组。注册清单、哈希与暴露记录见 `docs/experiments/`。只纳入有标注证据的主张，支持/反驳均可入选。
- 主指标 Complete@5：是否完整命中任一可接受证据集合。Coverage@5：对可接受集合取最佳覆盖。nDCG@5：标注证据句排序的辅助指标。

已知限制：样本较小，标注不一定穷尽所有相关证据；同一公开语料上的迁移不等于跨领域泛化；公开基准可能出现在基础模型训练中。本系统仍强制使用真实检索结果和数据中的证据 ID 计算指标。

原始论文：<https://aclanthology.org/2020.emnlp-main.609/>。许可：标注 CC BY 4.0，摘要 ODC-By 1.0，详见项目内 `data/scifact/LICENSE.md` 及 <https://github.com/allenai/scifact/blob/master/LICENSE.md>。

## 预算与日志

默认每轮最多 4 个候选、16k 模型 token、900 秒。调用前按限定上下文与最大输出保守预留，调用后使用 Ollama `prompt_eval_count`、`eval_count` 对账。规划、反思、无效输出修复和重试全部计入。若请求失败且拿不到 usage，预留量计为未知消耗，不记成零。

墙钟时间与工具耗时单独记录；云端调用始终为 0。不同运行只共享固定语料和索引，不继承查询结果缓存。Ollama 内部缓存会尽可能记录，但这不等于学习收益；比较时应同样预热模型，检查缓存统计。

取消在当前模型/工具调用结束后生效。达到预算时保留已验收方案；未完成独立验收的候选不可发布。服务重启将未完成运行标记为中断，不会自动继续消耗模型资源。

每次运行保存：数据哈希、代码哈希与后端源码快照、模型 digest、种子、输入输出、逐题排序、实验差异、预算与事件日志。导出 ZIP 可以离线检查。

## 命令行与复现

```powershell
py -3.12 research.py prepare
py -3.12 research.py run --task C --mode agent --experiments 4 --tokens 16000 --seconds 900
py -3.12 research.py run --task D --mode search --experiments 4
py -3.12 research.py publish <运行ID>
py -3.12 research.py run --task D --mode agent --use-memory --seed 42
py -3.12 research.py activate 0
py -3.12 reproduce.py runs\<运行ID>\run.json
py -3.12 -m unittest discover -s tests -v
```

Web 与 CLI 应避免同时运行研究，以免争抢本地模型和写入经验。复现命令重算检索排序和指标，不调用模型。重新请求 LLM 不保证逐字相同。使用导出包中的源码快照可检查对应实验的算法版本。

## 文件位置

| 路径 | 内容 |
| --- | --- |
| `researchloop/` | 数据、BM25、评估、Ollama、预算、研究控制与本地 API |
